## 1. 目标与范围

ExamHelper 是面向 Windows 11 x64、单屏使用场景的桌面答题辅助软件。通过全屏截图与麦克风语音识别组织问题，调用 AI 获取回答。用户希望尽量减少鼠标点击，因此辅助模式使用悬停触发、免点击移动与滚动以及可配置的全局快捷键；主页和设置使用常规交互。

应用启动后展示历史对话主页。只有用户选择“开始考试”，并满足服务测试和窗口保护初始化条件后，才进入半透明、置顶且设置了屏幕捕获排除属性的辅助小窗。历史文字和截图完整保存在本机，供以后查看。

首版采用 C#／.NET＋WPF。提供当前用户安装的 EXE 安装包，正常安装和运行不要求管理员权限。目标答题程序为普通权限运行的浏览器或桌面程序。

本文第 2～13 节汇总已经确认的需求及其直接推导出的交互规则。第 14 节保留补充建议的原始表述，用户已整体接受，实施时同样属于需求基线。具体依赖版本、文件划分和开发任务由实施计划细化。

### 首版不包含

不支持 Windows 10、ARM、多屏截图、区域框选或指定应用窗口截图；不采集电脑播放的声音，不运行本地语音模型。辅助模式不支持键盘输入、删除、换行或粘贴文字；文字仅通过麦克风语音识别追加，草稿区只读。主页和设置页仍可正常键入配置。回答不渲染一般 Markdown、数学公式、Mermaid 或生成图片，仅单独处理代码块。无需自动答题填写、自动提交到答题网页或自动执行生成的代码。

## 2. 窗口与生命周期

### 2.1 主页

启动时显示主页，可查看历史对话及其截图、管理记录、进入设置、点击“开始考试”。主页和设置使用常规鼠标点击和键盘输入。删除历史对话时弹出确认提示，删除对话的同时删除关联图片。

每次点击“开始考试”均创建一个新对话，不自动把选中的历史对话带入上下文。进入失败时留在主页显示原因。历史对话或退出草稿的显式恢复入口见第 14 节，不能改变“开始考试始终新建对话”的语义。

### 2.2 进入条件

AI 图片测试和语音识别测试均通过，才允许开始。AI 文字测试也在设置中提供。服务测试通过的结果随对应配置保存，日常启动无需重复发送测试请求。

修改 AI 服务配置后，AI 测试结果失效；修改语音服务配置后，语音测试结果失效。未修改的另一项服务保持有效。重新验证通过后恢复开始资格。

辅助窗口先在未展示状态完成捕获保护设置，初始化失败则不展示辅助小窗，保留主页并报告原因。成功后隐藏主页并展示辅助小窗。不能在保护设置前短暂展示答案窗口。

### 2.3 辅助小窗

小窗半透明、置顶，可调整透明度、移动、缩放，并记住上次的位置和尺寸。背景半透明，文字和按钮保持清晰。提供折叠／展开，折叠后仅保留顶部功能栏。展开时包括功能区、回答区、待发送截图区、文字输入区与发送操作区。小窗不提供设置入口，修改设置必须返回主页。

隐藏／显示小窗由快捷键控制。隐藏只影响显示并暂停悬停，不停止录音、识别或 AI 请求；辅助快捷键仍有效。折叠同样不清除草稿或停止任务。

### 2.4 返回主页与退出

| 操作 | 草稿 | 已发送对话及部分回答 | 正在进行的任务 |
| --- | --- | --- | --- |
| 返回主页 | 清除未发送文字、截图及语音撤销状态 | 保存 | 停止录音、识别、AI 回答，清除临时录音 |
| 退出软件 | 保存未发送文字和截图，供下次恢复 | 保存 | 停止录音、识别、AI 回答，清除临时录音 |
| 隐藏小窗 | 保留 | 保留并继续接收回答 | 继续 |
| 折叠小窗 | 保留 | 保留并继续接收回答 | 继续 |

返回主页后注销辅助模式的全局快捷键。退出是真正结束应用，不默认转为托盘后台运行。取消的异步任务晚到结果不得恢复草稿、重新打开窗口或写入新对话。

## 3. 悬停与免点击交互

### 3.1 统一规则

普通按钮悬停一秒执行一次；“返回主页”和“退出”悬停两秒。显示倒计时或进度，移出即取消。按钮触发后，持续停留不会重复执行，必须移出再移入才重新计时。禁用按钮不执行，关联快捷键也遵守相同限制。

窗口恢复、控件布局变化或删除图片导致新控件出现在鼠标下方时，不应直接开始新的悬停动作。悬停、快捷键和允许的点击入口统一进入相同命令及状态检查，避免同一动作执行多次。

### 3.2 移动与缩放

在标题栏的可拖动区域悬停一秒后，小窗跟随鼠标移动；停稳一秒后固定。右下角缩放手柄使用同样规则。标题栏按钮区域不属于拖动区域。操作期间暂停其他悬停计时，容忍轻微鼠标抖动，设置最小可用尺寸并避免窗口完全离开屏幕。

### 3.3 阅读滚动

回答区提供可见滚动条。在滑块上悬停一秒后进入免点击拖动，滑块改变外观；随后鼠标上下移动驱动滚动，允许横向偏离滚动条。停稳一秒后固定并退出拖动，必须移出再移入才能再次激活。

拖动期间暂停其他按钮的悬停计时。查看上方旧内容时，流式输出不能强制拉回底部；回到底部后恢复自动跟随。

## 4. 语音专用文字草稿与窗口交互

2026-10-17 用户实测后明确调整：取消辅助模式中所有键盘文本输入，文字只通过麦克风语音识别产生。草稿区改为只读预览，支持连续识别追加，不显示编辑光标，不接收键盘焦点；不支持键入英文、中文、删除、换行或粘贴。识别结果仍可使用“撤销本次语音输入”及“清空输入”管理，并与截图一起发送。

移除“取消输入”按钮及其快捷键、悬停聚焦、英文输入切换、输入法状态保存与恢复，以及输入框内 Ctrl＋Enter／Enter 规则。发送按钮和可配置的全局发送快捷键保留。主页和设置页继续使用正常点击与键盘输入，不受此调整影响。

辅助小窗在悬停、点击、折叠、缩放、滚动、删除图片和预览文字时均不主动请求激活或切换输入法，不需要用户通过“取消输入”返回答题界面。窗口显示时不自动激活，并处理鼠标激活消息以保持当前答题窗口的键盘输入。全局快捷键只执行相应命令，不将普通键盘文字输入导向草稿。

半透明不等于鼠标穿透；小窗功能区域仍接收鼠标事件。输入法候选窗不再属于辅助草稿功能的验证范围；答题程序自身输入法仍由用户正常操作。

## 5. 截图与草稿

### 5.1 两种截图入口

“截图并立即发送”获取当前单屏的完整截图，附上设置中的预置提示词并请求 AI。只有草稿为空且没有录音、识别或 AI 回答任务时可用。只要草稿有文字或截图，就禁用按钮与快捷键，并提示先发送或清空。

“截图加入待发送区”获取完整截图并追加到草稿，不立即请求 AI。可连续添加多张，允许在 AI 回答期间继续准备下一份草稿。截图内容应排除辅助小窗本身，实际效果必须验证。

### 5.2 图片管理

待发送区按添加顺序显示缩略图及序号，发送顺序保持一致。不提供拖拽排序或“移除最后一张”。鼠标在某张缩略图停留一秒后删除该图，显示倒计时，移出取消。删除后相邻缩略图即使移动到鼠标下面也不能继续触发删除。

“清空输入”同时删除全部未发送文字和截图，不删除聊天记录，也不重置当前对话上下文。清空后若没有其他任务阻塞，则恢复截图直发。

### 5.3 普通发送

普通发送提交当前草稿文字及全部截图，不自动附加截图直发预置提示词。允许只有文字、只有图片或二者组合，空草稿不发送。

AI 同时理解全部截图和文字：一道题跨图时合并处理，多道题时按截图顺序分别回答，用户具体说明用于明确本次任务。发送后草稿交接及失败恢复的并发细节见第 14 节。

## 6. 录音、识别与撤销

### 6.1 录音流程

只采集麦克风。悬停录音按钮或按对应快捷键开始，再次触发停止。显示正在录音状态与时长；单次最长 60 秒，到时自动停止并提交识别。识别结果追加到已有文字末尾，不覆盖原文，不自动发送，允许与截图一起提交。

首版采用阿里云百炼北京地域，优先使用 `qwen3-asr-flash`。语音服务与 AI 回答服务分别配置密钥；按中英混合场景自动识别，不固定为单一语种。停录后上传识别，不要求边说边显示实时转写。

### 6.2 撤销本次语音输入

识别结果填入后，立即显示“撤销本次语音输入”，正常显示三秒后消失。鼠标进入时暂停消失倒计时，悬停一秒撤销本次追加；移出但未触发时恢复剩余倒计时。

撤销仅影响最近一次语音追加，保留此前文字和全部截图，不提供“清空所有文字”按钮。发送或清空草稿后撤销入口失效。连续识别时采用第 14 节的增量记录规则，不能简单恢复整份旧草稿并覆盖后续识别结果。

### 6.3 失败处理

识别失败时保留临时录音，提供手动重试识别和丢弃录音。识别成功、丢弃、返回主页或退出时清除对应临时录音。录音不进入历史记录，不自动重复请求。

## 7. AI 配置、上下文与回答

### 7.1 服务配置

默认提供 KIMI 服务配置，同时支持自定义兼容接口，可修改 API 地址、密钥、模型名称。首版兼容目标是支持文字、图片消息及流式回答的 OpenAI 风格 Chat Completions 接口，不承诺任意提供相同字段的服务都可直接使用。KIMI 的具体图片模型名称在实施时根据官方文档及真实账户可用性确定，不硬编码未经验证的型号。

当前对话保留上下文。“新对话”创建独立上下文并保存旧对话。当草稿非空、正在录音、正在识别或 AI 正在回答时禁用该按钮及快捷键。清空草稿不等于新对话。

### 7.2 回答规则

默认使用中文。选择题、判断题先给出答案，再给简要理由；简答题直接给出作答内容；编程题直接给出代码，放在代码块中。默认编程语言为 C++，可以在设置中修改；题目明确要求的语言优先。

普通内容按纯文本显示并保留换行。代码块单独呈现，使用等宽字体并标注语言。首版不要求语法高亮或其他 Markdown 排版，数学内容尽量使用 `x^2`、`O(n log n)` 等可读的纯文本形式。

### 7.3 截图直发预置提示词

设置页提供可编辑、自动保存的预置提示词，仅用于“截图并立即发送”。默认内容如下：

> 请回答截图中的题目。选择题、判断题先给出答案，再给出简要理由；简答题直接给出作答内容；编程题直接给出代码，并使用代码块。多道题按截图顺序分别作答。

中文及默认编程语言由基础配置提供。留空时直发仅提交截图，但仍有应用的基础回答规则。历史记录保存实际发送的提示词，不在回看时用最新配置替换旧文本。

### 7.4 流式回答与中断

回答逐步显示。同一时间只允许一个 AI 回答请求，生成期间可继续通过语音准备下一份草稿和添加截图，但禁用发送及截图直发。提供“停止回答”，支持悬停和快捷键；停止后保留已收到的部分内容并标记未完成。

网络失败或中断保留已有内容，显示具体原因，手动重试，不自动连续调用。失败重试不应在上下文中重复插入同一份用户问题。

## 8. 关键命令状态表

所有命令都要求当前处于辅助模式；窗口隐藏不改变此条件。表中“空闲”指对应操作没有正在执行，不代表所有后台功能必须停止。

| 命令 | 允许条件或行为 |
| --- | --- |
| 截图并立即发送 | 草稿为空；无录音、识别、AI 回答；无重复截图提交 |
| 截图加入待发送区 | 可在 AI 回答期间执行；同一截图动作不重复并发 |
| 发送 | 草稿非空且无 AI 回答；录音、识别期间的限制见第 14 节 |
| 开始／停止录音 | 无录音时开始，录音时停止；识别期间不再启动同一录音流程 |
| 撤销本次语音输入 | 最近一次识别追加仍处于有效撤销时间窗 |
| 清空输入 | 清除文字和截图；处理异步识别的规则见第 14 节 |
| 新对话 | 草稿为空，且无录音、识别和 AI 回答 |
| 停止回答 | 存在正在进行的 AI 请求 |
| 折叠／展开、隐藏／显示 | 不清空内容、不终止任务 |
| 返回主页 | 两秒悬停；停止任务、清空草稿、保留历史 |
| 退出 | 两秒悬停；停止任务、保存草稿及历史 |

## 9. 设置与可用性测试

设置仅从主页进入。包含 AI 服务配置、语音服务配置及麦克风选择、截图直发提示词、默认编程语言、透明度和快捷键配置。API 密钥默认遮盖，不写入聊天记录或普通日志。

AI 测试分文字和图片测试，发出真实的小型请求，展示返回内容、耗时及可理解的错误，例如密钥无效、模型不存在、图片不支持和超时。图片测试使用内置测试图，不截取当前桌面。仅收到 HTTP 成功不足以判定图片识别正确，应展示实际识别结果供检查。

语音测试显示麦克风音量反馈，允许录制并识别一段中英混合语音，展示文本和耗时。测试可用句：“请用 Python 实现 binary search，并解释时间复杂度。”测试内容与正式对话隔离，不写入历史。

快捷键提供默认值并允许修改，检查应用内重复绑定与系统注册冲突。截图直发、截图加入草稿、开始／停止录音、发送、清空输入、新对话、停止回答、隐藏／显示、折叠／展开及返回主页／退出等命令共用同一状态判断。默认组合的具体建议在实施计划中集中列出，不占用普通打字或输入编辑按键。快捷键注册冲突必须明确显示，不能把注册失败当作可用。

## 10. 捕获保护与兼容性边界

对本应用辅助窗口使用 Windows `SetWindowDisplayAffinity` 与 `WDA_EXCLUDEFROMCAPTURE`。无需修改其他程序的窗口，不采用文章中用于操作第三方进程的 DLL 注入方案。创建新辅助顶层窗口或重建句柄后，必须重新应用并检查保护状态。

系统接口设置成功与实际录制不可见是不同层次的验证。微软明确说明此接口不保证阻止所有捕获方式，因此产品不能以接口返回成功宣称所有工具都已兼容。置顶、无焦点交互也不代表能够覆盖系统安全桌面或任意独占全屏程序。

| 验证对象 | 需要检查的路径 |
| --- | --- |
| Windows 截图工具 | 截图结果中辅助窗口是否被排除 |
| Windows 截图工具录屏 | 实际录像中的辅助窗口及交互反馈 |
| Xbox Game Bar | 支持的目标应用录制路径；不适用的模式标明不适用 |
| Chrome 发起的屏幕共享／录制 | 整屏、窗口等实际可选来源，检查接收或录制结果 |
| OBS | 显示器捕获与窗口捕获分别测试，记录捕获后端 |
| 腾讯会议 | 整屏和窗口共享，检查接收端或实际录像 |
| 应用自身截图 | 发送的截图不含辅助窗口及其遮挡伪影 |

每项记录 Windows 构建、工具版本、捕获模式和实际结果。检查窗口背景、文字、工具提示、悬停反馈以及聚焦／折叠／缩放过程中是否出现异常，不把所有“黑块”都等同于窗口完全排除。未在目标机器完成的项标记“未验证”，不能标记通过。

## 11. 本地数据与错误恢复

已发送的对话、截图及回答自动保存；未完成回答保留状态标记。数据放在当前 Windows 用户的数据目录，避免写入安装目录。密钥使用 Windows 当前用户范围的加密机制单独保存；聊天与截图本身没有额外的加密承诺。

删除历史对话时同时清理关联图片，仍被其他有效草稿或记录引用的图片不得误删。返回主页丢弃的截图、发送前删除的缩略图不应永久成为孤立文件。退出保存的草稿在下次启动提供恢复入口，原始语音录音不恢复。

普通发送失败保留请求的文字和图片。截图直发失败时，将原始截图和实际使用的预置提示词作为待发送内容保留，手动重试不重新截屏。部分回答保留并标记失败或停止。不能因为失败恢复覆盖用户在等待回答期间新写的草稿，具体交接见第 14 节。

日志记录必要的状态与错误，避免记录密钥、完整音频、截图内容和整份问题文本。服务返回的错误应转换为简明提示，同时保留可诊断的错误码。数据保存失败必须明确提示，不能报告已保存成功。

## 12. 架构与职责边界

应用采用 WPF 窗口与 MVVM 组织方式。UI 只显示状态及调用命令，耗时采集、文件操作与网络请求不阻塞界面。以取消令牌、会话标识和请求标识隔离异步结果，返回主页或新建会话后丢弃过期结果。

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| 主窗口与设置 | 历史查看、配置、测试、开始及恢复入口 | 不注册辅助悬停行为 |
| 辅助窗口 | 展示回答、截图草稿与输入区 | 不直接管理密钥和 HTTP 协议 |
| 交互控制器 | 悬停计时、互斥拖动、快捷键、命令可用状态 | 统一处理所有入口的状态限制 |
| Windows 交互服务 | 窗口保护、全屏截图、鼠标位置及不激活窗口策略 | 封装 Win32 调用，返回可检查的失败结果 |
| 麦克风与 ASR 服务 | 采集、60 秒截止、上传、重试、录音清理 | 不直接修改当前草稿，返回带标识的结果 |
| AI 服务适配器 | 配置、图文请求、流式解析、取消和错误转换 | 与界面渲染及本地数据库解耦 |
| 会话与草稿服务 | 上下文、发送快照、语音追加及撤销、失败请求 | 防止异步结果或撤销覆盖其他草稿变更 |
| 本地存储服务 | 历史、图片、退出草稿、配置、密钥 | 负责一致性保存、引用清理及恢复 |

本地记录建议采用 SQLite 加图片文件，配置采用结构化文件，密钥独立加密。该存储选择属于第 14 节的工程建议；是否采用具体第三方组件不改变已确认的用户行为。

不以嵌入浏览器作为回答渲染的必要条件。纯文本和代码块可使用 WPF 控件实现，流式期间保留尚未闭合代码块，避免回答抖动或丢字。

## 13. 实施顺序与验收

先完成书面设计审核，再编写实施计划和选择执行方式。当前仅交付设计文档，不在此阶段安装产品依赖或搭建应用。

第一阶段验证 Windows 核心交互：受保护窗口、免点击移动／缩放／滚动、不抢焦点的操作和只读语音草稿。尤其要在鼠标离开窗口后验证拖动仍可工作。验证结果决定是否需要调整窗口方案，不能先把聊天功能全部做完再发现基础交互不可行。

第二阶段接入截图、草稿、麦克风和 ASR，落实统一命令状态、三秒语音撤销及异步取消。第三阶段完成 AI 图文对话、流式回答、历史保存和设置测试。第四阶段完成当前用户 EXE 安装包、干净用户环境安装验证以及捕获兼容性矩阵。

### 主要验收场景

| 场景 | 预期结果 |
| --- | --- |
| 首次启动 | 主页展示，服务未验证时不能开始 |
| 修改一项服务配置 | 仅该项测试失效，重新通过后可开始 |
| 保护初始化失败 | 无辅助窗口闪现，留在主页并报告原因 |
| 开始考试 | 新建对话，隐藏主页，显示保护后的小窗 |
| 有草稿时截图直发 | 按钮及快捷键都不执行 |
| 多张截图与语音一起发送 | 图片顺序与文字完整，无自动附加直发提示词 |
| 删除缩略图 | 一秒后只删除目标图，不连续删除邻图 |
| 录音达到 60 秒 | 自动停录识别，文字追加，未自动发送 |
| 三秒语音撤销 | 暂停／恢复计时正确，仅移除对应语音增量 |
| AI 正在回答 | 可准备草稿，禁止第二个请求，可手动停止 |
| 免点击滚动与移动 | 激活、抖动容忍、停稳固定及悬停互斥正确 |
| 语音专用草稿 | 草稿只读且不可聚焦，无取消输入入口，语音结果可追加、撤销及清空 |
| 隐藏小窗 | 不停止任务，快捷键仍有效，无悬停误触 |
| 返回主页／退出 | 前者清空草稿，后者保存草稿；两者保存历史、清除临时录音 |
| 失败与重试 | 原请求可恢复，无草稿覆盖、重复上下文或自动重复计费请求 |
| 删除历史 | 确认后删除对话及其不再使用的图片 |
| 目标捕获工具 | 按第 10 节逐项提供真实结果，未测项不报告通过 |
| 安装与启动 | 普通用户安装、启动、卸载，无须开发环境或管理员权限 |

状态机、草稿增量撤销、失败请求恢复和持久化需要自动化测试；窗口捕获、不激活交互、实际录音及安装过程需要 Windows 集成或人工验证。使用模拟服务测试失败路径，真实服务验证需要用户在设置中提供有效凭据，不能用模拟通过代替真实服务可用性。

## 14. 本文补充的设计建议，随文审核

以下规则用于补齐此前未具体讨论的边界，最初作为随文审核建议；用户已于 2026-10-16 明确整体接受，实施时与前述需求同等适用。

### 14.1 草稿发送与失败恢复

建议发送时生成不可变的请求快照，原草稿转入该请求并清空草稿区，允许准备下一份草稿。失败时，若草稿区仍为空，将快照还原为草稿；若已有新草稿，保留新草稿，并将失败快照显示为独立的“待重试请求”，提供重试和丢弃。重试使用同一请求身份，不重复添加用户消息；一个失败请求未处理前可继续追加语音或截图，但禁止发送另一份请求，避免上下文分支歧义。

截图直发失败也适用该规则：空草稿区还原截图和提示词；非空草稿区不覆盖新输入。存在待重试请求时，禁用新对话及截图直发，用户先重试或丢弃。返回主页丢弃未发送的失败恢复内容，历史中已形成的失败记录保留；退出时保存恢复内容。

### 14.2 录音期间的命令与过期结果

建议录音或识别期间禁用普通发送，以免语音结果落入下一条消息。可以追加截图；识别结束后可再次录音追加文字。一次只执行一个录音／识别流程；有识别失败的待重试录音时，先重试或丢弃，再开始新录音。

“清空输入”可在此期间使用，但同时取消当前录音／识别、清除临时录音并废弃晚到结果，确保清空后不会突然再次出现文字。语音重试待处理也视为未完成的识别状态，阻止新对话和截图直发。

### 14.3 语音追加的撤销边界

2026-10-17 调整后，草稿不再支持手动编辑。每次识别追加记录本次文字及自动添加的分隔符，只删除该次增量，保留先前文字和全部截图。

新的识别结果到达时，以最新追加替换撤销对象并重置三秒计时；开始新录音时先关闭旧撤销入口。返回主页、退出、发送、清空、新对话均结束该临时入口；退出恢复草稿不恢复三秒计时。过期或其他会话的识别结果不能追加。

### 14.4 恢复历史与退出草稿

建议主页提供显式“继续此对话”，用于恢复选中的历史上下文或退出保存的草稿，进入辅助模式时同样检查服务资格和窗口保护。与“开始考试”入口并存，后者始终创建全新对话。历史查看只读，只有继续后才能发送。草稿按所属会话保存，开始新对话不自动删除其他会话已保存的退出草稿。

### 14.5 辅助窗口的取消操作

在移动、缩放或拖动滚动条期间，Esc 立即结束该交互并固定当前状态。隐藏、折叠或返回主页也结束正在进行的拖动。辅助草稿不接受键盘焦点，因此这些操作不切换输入法、不执行焦点恢复，也不向其他窗口模拟输入。

### 14.6 存储、上下文与请求大小

建议 SQLite 保存会话、消息、请求状态及图片引用，图片保留原始清晰度存储在独立目录。网络提交可以按所选服务限制另行编码，但不覆盖历史原图。写入采用事务或临时文件替换，失败时不误删原文件。

服务的图片数、请求体、音频大小及上下文容量以实际模型能力为准。超限时明确提示用户减少草稿或开启新对话，不静默丢弃图片、历史消息或自动总结上下文。首版不额外实现自动摘要记忆。

测试有效性建议绑定端点、模型及密钥等连接配置；语音还绑定采集设备配置。修改外观、提示词、默认编程语言和快捷键不使服务测试失效。已测试配置无法证明以后一直可用，运行时仍处理凭据失效或网络故障。

### 14.7 打包与默认界面

建议发布自包含的 win-x64 程序并封装为当前用户 EXE 安装包，不要求用户先安装 .NET SDK 或开发工具。安装器具体工具及 .NET 受支持版本在实施计划中选择。首版不增加自动更新或云端历史同步。

默认界面采用简洁、高对比的布局，背景透明度可调。代码块标注语言并允许正常阅读，不把完整 Markdown 渲染或语法高亮作为验收条件。具体尺寸、透明度、快捷键组合和抖动阈值作为可验证的默认参数在实施计划中列明，而非本阶段继续逐项提问。
