## 1. 目标、技术基础与范围

本版继续面向 Windows 11 x64，使用 C#／.NET 10＋WPF，提供主窗口聊天和受捕获保护的辅助窗口。主要目标是修复主窗口浏览、图片和模型配置问题，稳定历史列表，统一图标及悬停反馈，并增加批量删除、原图保存和回答计时。

沿用既有的每对话独立运行时、全应用单个 AI 生成任务、同 HWND 辅助控件、原生 Markdown 展示及单文件 HTML 导出。主窗口使用正常点击和键盘输入；辅助窗口不接受键盘文本编辑，文字仍由麦克风语音识别追加。

实现路线采用在现有 Core／Windows／WPF 分层上定向修改。重做整个聊天渲染系统会扩大回归范围；引入浏览器渲染则增加辅助窗口焦点及捕获保护的验证成本。本版保持现有原生 WPF 展示，分别处理列表更新、滚轮路由、图片坐标和控件模板，不进行无关的框架替换。

以下章节中的交互结果来自本轮确认；字段名称、独立数据目录及控件拆分属于本设计给出的实现安排，供本次文档一并检查。

## 2. 全新应用与数据隔离

0.4.0 按全新应用初始化，不读取、复制或继承 0.3.0 的 AI 配置、密钥、测试资格、聊天记录、草稿、图片及窗口设置，也不安排旧库迁移或旧版资料兼容。本版的初始化不能因为机器上还存在旧文件，就重新导入旧配置。

设计采用独立数据根目录 `%LOCALAPPDATA%\ExamHelper\0.4`，本版的设置、受当前用户保护的密钥、历史数据库、原图和临时录音均位于其下。后续同属 0.4 系列的修订继续使用该目录，不因每次升级补丁版本而清空。第一次使用为空白状态，之后重启正常恢复本版保存的数据。

安装身份和默认程序目录与 0.3.0 分离，默认程序目录为 `%LOCALAPPDATA%\Programs\ExamHelper-0.4`，界面产品名称仍为 ExamHelper。以数据目录隔离实现“全新应用”，不依赖自动删除旧版文件。旧版遗留文件不参与本版运行，也不是安装前必须完成的迁移步骤。

0.4.0 的重启恢复、原子保存、保存失败重试及崩溃后的任务状态恢复仍需验证；“不考虑旧版资料”不等于本版不保存数据。

## 4. AI 设置：空白起点、完整性与模型目录

### 4.1 首次打开和新增配置

首次打开 AI 服务页时，配置列表为空，只显示添加配置入口。没有默认 Kimi 配置，也没有预填的名称、API 地址、密钥或模型。点击“添加配置”后得到独立空白配置，不继承另一个配置的字段、模型、拉取结果或验证状态。

表单的主要顺序为：**配置名称 → API 地址 → API 密钥 → 模型拉取／模型管理 → 默认模型及模型思考设置 → 所选模型测试**。API 密钥紧接 API 地址，使用掩码输入框，不再放在页面末尾；不恢复“服务类型”字段。

未完成的配置允许保存，方便下次继续填写。空白字段按空白保存，不用默认 Kimi 地址、默认模型或占位名称替代。列表可用“未命名配置”作为显示占位，但不把它当作用户已填写的名称。

缺少配置名称、有效 API 地址、密钥或可用模型／默认模型时，标记为“未完成”，暂不可调用。这类配置不会阻止保存其他设置，也不会阻止进入辅助模式。主窗口中，资料完整即允许直接尝试调用，不要求服务测试。

### 4.2 模型新增、选择和去重

继续支持从该配置接口拉取模型，以及手动填写真实模型 ID。拉取结果只属于发起请求时的配置、地址和密钥；切换配置或修改相关字段后，过期结果不能写入当前配置。用户勾选所需模型后加入，不自动把所有结果导入。

“添加模型”使用独立的新模型 ID 输入，不复用当前已选模型的名称绑定。空名称不能提交；重复加入同一模型不产生副本。加入成功后选中新条目，不清空原有模型，也不把原模型改为空白。手动输入及接口结果均去除首尾空白、拒绝空项，并按真实模型 ID 去重。

问题参考见[用户提供的模型列表截图](D:/Code/ExamHelper/artifacts/assets/examhelper-0.4/ai-model-bug-reference.png)。新增配置的模型列表必须真正为空，不能由兼容字段或归一化逻辑补回 `kimi-k2.6`。反复添加、切配置、保存、关闭设置及重新打开后，都不能产生幽灵 Kimi 模型或不断增长的空白条目。

每配置继续设置一个默认模型。模型已存在但默认模型尚未指定时，允许保存为未完成状态；用于正常调用前须补齐。删除默认模型后，不静默指定另一项，应让用户重新指定，或保存为未完成配置。

### 4.3 思考设置及凭据

沿用每模型独立默认思考设置、已确认能力适配及手动覆盖。不能确认支持的模型只使用服务默认值。窗口中的思考调整仅影响该对话的后续请求，不覆盖设置中的默认值。

调用绑定发送时选择的配置、模型、参数及凭据快照；准备请求时的密钥读取仍须受保护。修改或删除配置不能使已经准备中的请求读到被提前清理的旧密钥，也不能把调用自动转给另一个服务。

## 5. 测试资格与辅助模式准入

### 5.1 进入条件

AI 或语音尚未测试通过，不再阻止点击“开始考试”。辅助窗口仍必须成功初始化捕获保护；保护初始化失败时留在主页并显示实际原因。这项 Windows 保护要求继续保留。

首次 AI 列表为空、没有合格模型、语音未配置时，也可以进入辅助窗口。此时仍可查看界面、截图入草稿、移动、缩放、折叠、隐藏或返回主页；对应服务功能按下列规则禁用。

### 5.2 AI 按模型独立启用

每个模型分别保存**文字测试**和**图片测试**结果。只有两项都通过，且当前配置资料完整，该模型才允许在辅助模式中调用。只有一项通过、两项都未通过或测试失败，均为不可调用。

未通过模型保留在模型列表中并置灰，而不是过滤隐藏。同一配置内其他合格模型正常可用；不能因为一个模型不合格，就禁用整个配置的所有合格模型。配置中没有合格模型时仍可查看其模型列表，但不能向这些模型发送请求。

选择配置时，默认模型合格则加载该默认模型；默认模型不合格而其他模型合格时，明确展示合格模型供用户选择，不自动选取替代模型。未形成有效合格选择前，发送、截图直发及调用 AI 的重试入口均不可用。切换配置、模型时保留已有上下文、文字和图片草稿，已启动回答不受影响。

地址或密钥变化，使该配置全部模型的两类测试资格失效；修改模型 ID，只使该模型的两类资格失效；改变思考档位不要求重新测试。测试资格只记给测试时的配置及模型快照，不给后来改动的字段记通过。

主窗口聊天维持零测试门槛：资料完整即可尝试，失败返回实际错误，内容保留，用户手动决定重试。不会把辅助窗口的测试限制套用到主窗口。

### 5.3 语音功能单独启用

语音识别未测试通过时，**仅禁用录音功能**，不阻止进入辅助模式，不妨碍截图入草稿或合格 AI 模型的使用。录音快捷键与按钮执行相同资格判断，不能借快捷键绕过禁用状态。

语音测试继续采用测试录音、返回结果及用户确认“识别正确”的流程。语音配置变化使其资格失效。已通过时保留仅麦克风、单次最长 60 秒、手动开始／停止、识别结果进草稿及三秒撤销的既有规则。

## 6. 主窗口布局、消息复制与滚动

主窗口顶部保留使用说明、设置和开始考试。左侧为历史列表；原“改标题”及单条删除工具栏入口由条目上的图标替代，顶部增加“批量编辑”。“导出 HTML”从历史列表工具栏移至输入框下方操作行最右侧，文字改为**“导出”**。

主窗口输入框下方移除“清空输入”按钮，保留发送、停止以及按任务状态出现的重试／丢弃入口。辅助窗口的清空输入功能及其既有快捷键不因这项主窗口布局变更而移除。Enter 发送、Shift＋Enter 换行继续保留，输入法选词不能触发误发送。

每条用户提问和 AI 回答顶部提供复制图标。点击复制该条消息的完整原始文字：AI 回答保留 Markdown 标记、代码围栏和表格源码；用户提问保留原文。复制结果不包含图片、时间、角色标签、模型、用时或内部推理内容。代码块原有的单独复制功能继续只复制该段代码。生成中的回答复制当前已经收到的内容。

修复指针位于代码块时滚轮无法翻页的问题。普通竖向滚轮在代码区也驱动外层聊天内容滚动，不被仅负责代码横向显示的内层滚动容器吞掉；代码横向滚动条仍可正常操作。流式更新时继续保持用户阅读位置：用户向上翻看后，不因新内容或计时刷新而拉回底部。

## 7. 图片输入、预览与保存

### 7.1 草稿缩略图

主窗口草稿图片继续以圆角缩略图展示。点击图片主体打开完整图片预览，**只有点击右上角叉号才删除该图**。叉号为独立命中区域，点击删除不能同时打开预览；查看图片不能修改草稿。删除和异步导入始终绑定所属对话，切换聊天后不能误改另一条草稿。

修复 Ctrl＋V 无法粘贴复制图片的问题，同时保留文件拖入。剪贴板图片和拖入文件走同一导入通道；支持系统位图及常见应用提供的图片格式，不能只接受某一种运行时 Bitmap 类型。剪贴板同时提供图片和描述文本／HTML时，优先作为图片导入，避免多插入一份说明文字或 URL；只有普通文本时保持正常文字粘贴。

沿用 PNG、JPEG、BMP、GIF 首帧、TIFF 首页的完整像素导入规则，统一保存 PNG，不自动缩小原图，不因粘贴自动发送。不支持的内容给出实际错误并保留原有草稿。

### 7.2 完整预览

草稿图片与历史消息图片共用同一个预览窗口。修复辅助模式截图在主页打开后仅显示左上四分之一的问题，预览必须使用完整原图，正确处理图片像素尺寸、图片 DPI、窗口 DIP 及缩放／平移变换。

首次打开适应可视区域，整幅图片的四边及四角均可见；维持滚轮缩放、鼠标拖动平移、Esc 关闭。窗口变更尺寸和跨 125%／200% 显示器时，不能重新出现四分之一裁切、拉伸或坐标偏移。缩略图、预览、保存和 HTML 导出都引用同一张完整原图，而不是把缩略图放大冒充原图。

### 7.3 保存

两种来源的预览窗口均提供“保存”。点击后使用系统保存对话框，保存完整尺寸 PNG；预览缩放和平移不影响保存内容。已有目标文件由系统询问覆盖，取消不写文件；缺图或写入失败显示错误，不能破坏已有目标文件。保存图片不改变聊天记录或原图引用。

## 8. 历史时间、稳定排序与选中状态

每条对话具有持久的创建时间。历史排序时间与内部“最后保存时间”分离，保存草稿、查看、改名及刷新不应改变聊天活跃时间。

有聊天消息时，排序依据取消息顺序中最后一条用户消息或 AI 回答的创建时间，按该时间倒序排列。流式回答只是更新已有回答正文，不能把该条消息的创建时间改成每次收片段的时间，也不能每秒移动条目。

只有草稿、尚未发送消息的对话，按对话创建时间参与同一列表的倒序排列，编辑草稿不改变位置。首次发送后切换到最后消息创建时间。时间相同的条目使用固定次级键保持相对顺序。打开对话、在条目间来回切换、重命名及重试原回答均不因保存或刷新而重排；真正新增提问／回答才按上述依据更新位置。

标题下灰色小时间显示同一排序依据，固定转换为 **UTC＋8**；纯草稿显示创建时间。默认标题继续采用“对话＋第一次发送时间”，不随后续发送更新，手工标题不被自动覆盖。对话标题和消息的可见时间也统一按 UTC＋8 格式化，计时耗时则独立计算。

历史列表按稳定对话 ID 增量更新，保留条目对象、选中项及滚动位置，不在每次流式片段或计时跳秒时清空重建。修复选中蓝色框反复闪动；新消息应更新相应数据，不反复取消再恢复同一个选中项。

## 9. 重命名、单条删除及批量编辑

### 9.1 条目操作

普通模式下，鼠标悬停在某条对话时，其右侧显示重命名、删除两个图标，不添加文字按钮。图标可有简短工具提示和可访问名称。点击图标针对该条对话执行，不误触其他条目或批量勾选。重命名继续持久保存；单条删除仍需确认。

### 9.2 批量勾选与预览

点击“批量编辑”后，每条对话左侧显示复选框，顶部提供“全选／取消全选”“删除所选”“完成”，并显示已选数量。“全选”针对整个历史列表，不局限当前可见的几行。

点击条目主体，同时切换该条的勾选状态并打开该对话，便于核对内容；单独点击复选框只调整勾选，不切换聊天。勾选状态按对话 ID 保存，异步刷新及排序不能勾错对象。此模式下主要删除入口为“删除所选”，完成后恢复普通条目操作。

### 9.3 删除及失败处理

“删除所选”只弹出一次确认，明确将删除多少条对话。确认后对目标 ID 的冻结列表逐条处理；有正在生成、录音或识别的目标对话，先停止这些对话的任务再删除。未被选中的对话及其后台任务继续运行。

删除成功的条目正常移除，不回滚；失败条目留在列表中并保持勾选，显示失败原因，方便重试。失败不能先释放正在查看的运行时，导致用户随后无法编辑、切换或退出。成功删除后，迟到回调或异步导图也不能重新创建该对话。

删除记录后清理不再被任何持久或内存引用使用的原图；不能误删其他对话、待提交导入或正在导出使用的图片。历史删除成功但孤立文件清理失败时，分别报告文件清理结果并保留清理重试能力，不把已删除历史重新插回。

当前正在查看的对话成功删除后，自动打开剩余列表中最新的一条；没有剩余对话时显示空白新对话。消息和文字／图片草稿均为空时，不产生持久历史记录。若当前对话删除失败，继续保留它供查看、编辑或重试。

## 10. 辅助窗口三排布局与悬停反馈

第一排为新对话、停止回答、折叠／展开、返回主页、隐藏、提示；第二排为配置、模型、思考选择；第三排为截图直发、截图入草稿、开始／停止录音、清空输入、发送。第一排和第三排采用与第二排一致的横向自适应方式：各排按钮占满可用宽度，均衡分配空间，不全部挤在左侧。

在既有最小尺寸 480×360 至默认尺寸、横向缩放和不同 DPI 下，按钮文字可读，三排及发送操作均可触达。撤销和失败重试等条件操作显示在主操作行之后的独立自适应区域，不把第三排的主要五项挤出窗口。折叠状态只影响正文区域，折叠／展开按钮继续按下一动作显示文字。

所有辅助悬停按钮的进度线紧贴按钮外侧，沿圆角矩形外轮廓顺时针绕行，从顶部中央开始，到达触发时长时刚好绕满一圈。取消原来位于底边的直条进度。轮廓随控件真实尺寸变化，不能在缩放时断开、越界或挤压文字。

普通按钮为绿色、1 秒；返回主页和隐藏为红色、2 秒。配置／模型／思考入口及选项、代码复制等悬停按钮均使用这一轮廓样式。指针离开立即重置，同次停留只触发一次；布局改变、删除后新控件移动到指针下方，不能触发连续误操作。移动／缩放期间继续暂停其他悬停动作，禁用控件不积累可触发进度。

待发送图片删除保留例外：灰色遮罩、中央白圈和叉号、外围红色圆环，一秒完成删除。它不改为沿缩略图四边绕行。辅助模式的控件和进度均绘制在同一个受保护 HWND 中，继续不抢答题界面焦点。

## 11. 回答计时与导出

### 11.1 起止点及展示

主窗口和辅助窗口使用同一条请求的计时状态。从发送动作被接受、进入实际发送流程时开始，包含本地发送准备、等待首字和后续生成全过程。因全局任务占用或配置不可用而未被接受的发送，不生成一条假回答及计时。截图直发以截图成功并进入发送流程为起点。

生成中显示“已用 12 秒”，每秒更新；正常完成后显示“用时 12.4 秒”。失败或手动停止时显示对应状态及本次耗时，退出应用取消任务时同样结束计时并保存。耗时与 AI 回答关联，显示在回答头部或紧邻的状态位置，不混入可复制正文。

切换聊天、返回主页、隐藏／折叠或收起到托盘不重置计时。A 在后台生成、用户查看 B 时，A 仍按自身请求计时；重新查看 A 能显示正确结果。每次重试从 0 重新开始，显示并保存本次尝试用时，不累加上次失败或停止的时间；没有重试则保留原用时。

时间测量使用单调时钟，不能用 UTC＋8 显示时间相减而受系统校时影响。最终耗时持久保存，重启和切换视图后不重新计时，也不根据消息文字长度推算。没有计时数据的记录不补算。

### 11.2 HTML

输入框下方右侧的“导出”仍导出当前对话的单文件离线 HTML，内嵌完整图片及样式，保留 Markdown 排版。图片在所属提问文字上方，不集中放到末尾；不含草稿、密钥、内部配置或供应商内部推理。

导出包含每条回答的用时。生成中的回答导出当前已收到内容及导出瞬间的已用时间，保持部分回答状态；导出文件冻结后不再继续跳秒，也不改变正在进行的请求。取消、缺图及写入失败不得覆盖已有有效导出文件。

## 12. 精简文案与使用说明

## 13. 模块与数据设计

Core 继续负责会话、草稿、消息、请求及资格规则。设置数据能表达空配置和未完成配置；每模型分别持有文字、图片测试证据，完整性与测试资格分别判断。会话增加稳定创建时间，摘要暴露独立排序时间；回答／请求增加单次尝试的计时及最终耗时，时间刷新不触发整份历史重建。

Windows 层负责独立数据路径、加密密钥、持久化摘要排序、剪贴板／文件图片解码、原图读写、受控测试和安装资源。沿用原子写入、图片引用生命周期保护和准备请求的凭据租约。本版新建数据库与设置格式，不以移除旧迁移流程为由削弱本版文件损坏时的错误处理。

WPF 层将历史条目状态、批量选择和消息正文更新分开；主窗口以稳定 ID 增量同步历史；图片主体预览与叉号删除分开命中；预览器统一像素与 DIP 变换并提供保存；辅助按钮共用外轮廓进度控件。使用现有 Markdig 解析和代码着色规则，保留现有 Markdown 安全范围。

消息原始文字、完整原图、显示时间、计时和内部供应商字段保持清楚边界：复制取原始正文，图片保存取原图，HTML取安全渲染及冻结用时，灰色时间取历史排序时间；不能用内部保存时间代替聊天时间。
