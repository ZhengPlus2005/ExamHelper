# ExamHelper

**面向 Windows 11 的截图、语音与 AI 对话辅助工具。**

简体中文 | [English](README.en.md)

ExamHelper 将普通聊天主页与置顶辅助小窗结合起来，支持截图提问、麦克风语音转文字、多模型切换和本地对话管理。它适用于学习、题目练习、代码讨论，以及规则明确允许使用外部工具的辅助场景。

当前应用界面以简体中文呈现，英文版为使用文档，不代表应用已支持多语言界面。

当前版本为 **0.4.0**，使用 **C# / .NET 10 / WPF** 开发，仅支持 **Windows 11 x64**。辅助窗口通过 Windows 官方 API 请求从受支持的屏幕捕获结果中排除；这项功能有明确边界，不能视为绝对隐身或防检测能力。

## 功能概览

| 模块 | 当前支持 |
| --- | --- |
| 主页聊天 | 文本输入、流式回答、上下文、多图提问；Enter 发送，Shift + Enter 换行 |
| 截图提问 | 截取辅助窗口所在显示器；截图直发，或积累多张截图后一起发送 |
| 语音输入 | 只录麦克风，手动开始／停止；最长 60 秒，识别后填入草稿而不自动发送 |
| AI 配置 | 多个兼容接口配置；拉取或手动添加模型；默认配置、模型和思考深度 |
| 辅助小窗 | 置顶、半透明、捕获排除、悬停操作、免点击移动／缩放、可配置快捷键 |
| 回答阅读 | Markdown、代码块、代码复制、鼠标滚轮浏览；每条消息可复制原始 Markdown |
| 图片管理 | 粘贴、拖入、缩略图、完整原图预览、缩放／平移、保存原始 PNG |
| 历史管理 | 自动保存消息与草稿、重命名、批量删除；按最后消息创建时间排序 |
| 导出与计时 | 图片内嵌的单文件 HTML；逐次请求计时，重试从零开始 |
| 后台运行 | 关闭主页收起到托盘，单击恢复，右键正常保存后退出 |

AI 服务、截图理解和语音识别需要对应供应商的接口与密钥。软件不内置可直接使用的 AI 账号，也不提供 API 额度。

## 安装

使用 Windows 11 64 位系统，运行 `ExamHelper-Setup-0.4.0-x64.exe`。安装范围为当前用户，正常安装不要求管理员权限。安装完成页的“启动应用”和“添加快捷方式到桌面”默认勾选，可自行取消。

安装包包含 .NET 运行环境，无需另装运行时。若使用自包含发布目录，必须保留整个目录，不能只复制 `ExamHelper.App.exe`。交付文件旁提供 `.sha256` 校验文件；版本号相同的重建包应结合散列及 `build-info.json` 中的提交识别。

## 快速开始

### 1. 配置 AI 服务

打开主页右上角的“设置”，在“AI 服务”中添加配置，填写配置名称、API 地址和密钥。首次安装不预填供应商、地址或模型；可自行配置 Kimi 或其他兼容 OpenAI Chat Completions 接口的服务。

点击“拉取模型”可尝试读取供应商的模型列表，再勾选加入。接口不支持模型列表时，可直接在可编辑的模型下拉框输入模型名称，点击“添加模型”。模型名称及图片、思考能力必须与供应商实际支持的接口一致；能拉取到模型不代表它一定支持图片。

选中配置并点击“设为考试默认配置”，选择其“考试默认模型”，再选中该模型设置默认思考深度，保存后生效。界面中的“开始考试”是进入辅助模式的入口名称；是否可以在具体场景中使用，仍取决于该场景的规则与授权。

**文字测试和图片测试仅用于自测，不是聊天的前置条件。** 未测试或测试失败的模型仍可尝试调用，失败时显示错误，由用户手动重试。未填写完整的配置可以保存，实际调用仍检查必要配置和思考选项是否合法。

### 2. 配置语音识别（可选）

当前云端语音方案使用阿里云 DashScope 北京地域兼容接口，默认模型为 `qwen3-asr-flash`。填写语音服务密钥、选择麦克风，使用测试录音核对识别结果并确认。面向中文、英文及中英混合输入使用，实际识别质量取决于服务、麦克风和环境。

语音识别未测试通过时，只禁用录音，不限制主页聊天或进入辅助模式。当前不录制系统播放声音或会议中的远端音频。

### 3. 在主页聊天

新建对话或选择历史记录后，输入文字并发送。可用 Ctrl + V 粘贴图片，也可拖入 PNG、JPEG、BMP、GIF、TIFF 文件；动态图取首帧。图片先进入待发送区，不会自动提交。

点击草稿图片主体可放大查看，只有右上角叉号会删除该图片。已发送图片显示在所属提问的文字之前，可查看完整原图并保存。每条消息的复制按钮复制原始 Markdown 文本，不包含图片或时间信息；代码块内的复制只取代码。

### 4. 使用辅助模式

点击“开始考试”会创建新对话，加载设置中的默认配置、模型与思考深度。只有辅助窗口捕获保护初始化成功后才进入；失败时停留在主页并提示原因。

辅助小窗不接受键盘文字，文字通过麦克风识别加入。录音最长 60 秒，到时自动停止并提交识别；结果加入草稿，不自动发送。识别后有三秒撤销入口，仅撤销本次语音；鼠标进入撤销按钮时暂停倒计时。

“截图直发”仅在草稿为空且没有冲突任务时使用，并附加设置中的直发提示词。“截图入草稿”可积累多张截图，再与文字一起发送。截图范围是小窗所在的完整显示器；跨屏时按窗口最大重叠面积确定，不支持鼠标框选区域。

普通按钮悬停一秒触发；返回主页和隐藏为两秒，红色外围进度表示触发倒计时，移开即可取消。模型、配置和思考选项先悬停展开，再悬停选中。辅助草稿图片悬停一秒会删除，主页图片仍使用右上角叉号删除。

标题栏和缩放手柄支持悬停开始移动／缩放，停稳一秒固定，Esc 取消。回答和草稿使用正常鼠标滚轮。小窗默认背景不透明度为 50%，可折叠、展开或隐藏。隐藏不终止当前回答和识别，快捷键仍可使用。

### 5. 保存、导出与退出

对话及未发送草稿按对话自动保存。切换对话、返回主页或重启后，草稿恢复到输入区；未发送内容不会伪装成已发送消息。没有消息和草稿的空对话不保留。返回主页不会中断回答；录音会停止并提交识别，结果仍回到原对话。

历史记录可重命名或批量删除，删除前会确认。历史列表、消息和 HTML 的显示时间统一为 UTC＋8。“导出”生成图片内嵌的离线 HTML，不包含未发送草稿、API 密钥或内部推理字段；生成中导出会冻结当时的内容与用时。

主页的“×”收起到系统托盘。单击托盘图标恢复；辅助模式下该操作会返回主页。右键“结束进程”会取消任务、保存已收到的回答和草稿，保存失败则继续运行并提示重试。

## 技术实现

界面采用 WPF，业务与请求状态放在 `ExamHelper.Core`，Windows 平台能力放在 `ExamHelper.Windows`。AI 请求使用兼容 Chat Completions 的 HTTP 接口和流式响应；截图直接作为图片发送给支持视觉的模型，没有单独的本地 OCR 流程。模型切换只影响后续请求，全应用同时只生成一条 AI 回答。

整屏截图使用 GDI `BitBlt`，显示器选择和窗口几何使用 Win32 API；录音通过 NAudio 采集麦克风，文字交给云端语音服务识别。历史记录使用 SQLite，完整截图保存为独立 PNG。Markdown 使用 Markdig 解析并由 WPF 控件呈现，代码区域使用 AvalonEdit；HTML 导出禁用脚本和远程图片。

辅助窗口通过 P/Invoke 对**本进程的顶层窗口**调用 `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)`（`0x11`），并用 `GetWindowDisplayAffinity` 回读确认。此方式依赖 Windows 的桌面合成与捕获机制，**不向答题软件或录屏程序注入代码**。模型菜单和快捷键提示保持在同一受保护 HWND 中；置顶和不抢焦点是另外的窗口交互机制。

微软明确说明，显示亲和性只覆盖特定系统捕获功能，不是 DRM 或严格的安全保证。详见 [SetWindowDisplayAffinity 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。

## 功能边界与反捕获范围

捕获排除不等于进程隐藏、反检测或系统级保密。软件仍有普通进程、窗口、托盘和网络请求。它不隐藏进程、不修改录屏软件、不解除其他程序的捕获保护，也未实现驱动级防护或反注入对抗。主页、设置页和系统对话框不自动继承辅助窗口的捕获排除属性。

| 项目 | 当前证据或边界 |
| --- | --- |
| Windows 自带截图／录屏、Chrome 屏幕共享 | 用户曾在其当时的环境中验收通过，不代表所有版本、设置和设备均有效 |
| 自有参考画面的 GDI 捕获 | 受控检查通过；辅助窗口保护读回 `0x11`，捕获画面与参考画面对比通过 |
| 双屏和 DPI | 已有负坐标双屏及 125%／200% 缩放下的受控验证，不覆盖所有显卡、驱动和显示组合 |
| OBS、腾讯会议及其他捕获后端 | 尚无足够实测证据，不作兼容性或不可捕获保证 |
| 物理拍屏、外部采集、进程被控制或系统级采集 | 不属于当前机制可以提供可靠保证的范围 |
| 防绕过与“反反捕获检测” | 尚未实现；属性回读成功不能证明所有捕获路径都看不到窗口 |

其他程序启用 ACG 或防注入，本身通常不直接影响本方案，因为软件没有向这些进程注入代码；其他捕获限制、桌面隔离等仍可能影响使用。对 ExamHelper 自身强制启用严格 ACG 需要另做 .NET JIT 兼容性验证，不能当成已支持的加固选项。参见 [微软 Exploit Protection 说明](https://learn.microsoft.com/en-us/defender-endpoint/exploit-protection-reference)。

当前仅支持 Windows 11 x64，不支持 macOS、Linux、区域截图、系统音频采集或离线语音识别。软件可生成文字和代码，不提供图片生成、Mermaid 图形渲染或专业数学公式排版。尚未提供专门的面试辅助流程。

## 数据与隐私

0.4 系列本地数据位于 `%LOCALAPPDATA%\ExamHelper\0.4`，默认安装目录为 `%LOCALAPPDATA%\Programs\ExamHelper-0.4`。首次使用为空白配置，不导入旧系列数据；已有 0.4 数据会在本版重启后恢复。

API 密钥按当前 Windows 用户使用 DPAPI 加密保存。**这不代表历史记录和图片整体加密。** SQLite 历史、完整 PNG 和导出的 HTML 可能包含敏感信息，复制、备份或分享前请自行检查。删除历史会清理不再被引用的关联图片，不承诺安全擦除或删除外部备份。

发送 AI 请求时，相关问题、截图与对话上下文会发送到所配置的供应商；语音识别会将录音发送到语音服务。数据不会因为桌面窗口启用了捕获排除就变成“完全本地处理”。请了解供应商的数据保留、计费和隐私政策，避免发送无权处理的内容。

## 从源码构建

在包含 `ExamHelper.slnx` 的完整源码目录执行。开发环境需要 Windows 11 x64、PowerShell 7，以及 `global.json` 锁定的 .NET SDK（当前为 `10.0.402`）；生成安装器还需要 Inno Setup 6。脚本支持用 `-DotnetPath` 指定 SDK 路径。

```powershell
# 锁定依赖恢复、构建与测试
./scripts/Test.ps1 -Configuration Release

# 发布自包含应用
./scripts/Publish.ps1 -Version 0.4.0 -OutputDirectory ./artifacts/publish/win-x64

# 生成安装器；把路径替换为本机 ISCC.exe 的位置
./scripts/Build-Installer.ps1 -Version 0.4.0 `
  -IsccPath 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe' `
  -PublishDirectory ./artifacts/publish/win-x64 `
  -OutputDirectory ./artifacts/installers
```

主要目录为 `src/ExamHelper.App`（界面）、`src/ExamHelper.Core`（业务）、`src/ExamHelper.Windows`（平台适配）、`tests`（回归测试）及 `tools/ExamHelper.InteractionLab`（受控验证工具，不随安装器分发）。第三方依赖声明见完整源码中的 `THIRD-PARTY-NOTICES.md` 和 `packaging/licenses/`。
